# Agent Note: 归档封印用只增不改的封印史，而不是单个哈希清单

Status: implemented

## Problem

归档笔记的冻结契约原本只靠 `archived/manifest.json` 里一张 `路径 → sha256` 的映射表。哈希值本身写在同一个可写文件里，没有任何外部锚点，于是"防止篡改"退化成"和自我保持一致"：

删掉 `manifest.json`，再按文档推荐的补封印命令跑一次 `verify-archived-agent-notes.ts --write`，被改过的归档正文就会**静默获得一个新封印**，此后一切正常。README 里"谁动了归档里的一个字，校验当场报警"这句承诺因此不成立。

更糟的是，这条绕过路径是**我们自己写进文档推荐流程的**（"历史包袱补齐"一节），使用它的人不会觉得在做危险操作。

## Decision

封印拆成两个文件，职责不同：

- `archived/manifest.json`——派生索引，`路径 → sha256`，可以随意重写；
- `archived/.seal-ledger.json`——**只增不改的封印史**，每条记录带一个链接到前一条的链式哈希 `sha256(prevChain + "\n" + key + "\n" + seal)`。

校验顺序固定：**先**用链式哈希验证封印史自身完整（改、删、重排任何一条都会断链），**再**拿封印史里的值比对磁盘内容。封印史知道某个 key 时，manifest 只能作为旧仓库的回落来源，不能覆盖它。

写入口径也一并收紧：

- `verify-archived-agent-notes.ts --write` **只新增**，绝不重封封印史已知的内容；
- 要采纳一处编辑必须显式 `--reseal`，它会逐条打印被改动的条目；
- 封印史存在而 `manifest.json` 丢失时，拒绝隐式重建；
- 在 git 基线对照下，新增的封印还必须对应基线里**存在**的 `implemented/` 笔记——手放进 `archived/` 的笔记拿不到合法封印。

两个文件共用 `scripts/seal-store.ts`，归档 CLI 与校验器不会各自实现一套。

## Alternatives considered

- **给封印加 HMAC 或签名**——这是唯一能真正防篡改的做法，但密钥要么进仓库（等于没有），要么进 CI secret（本地就退化），并且把"零配置、`npx tsx` 直接跑"这个核心卖点换掉了。留下的是更差的中间态：看起来有密码学保护，实际取决于密钥管理，而本项目没有任何密钥管理。放弃。
- **只保留单个 manifest，但让 `--write` 拒绝任何已存在条目**——能挡住重封，却挡不住"删掉整个文件再重建"，因为删除后没有任何东西能证明曾经封印过什么。实测确认这条路径可绕过，因此单独一个文件不足以承载冻结契约。
- **把 manifest 提交进 git 就够了，不做封印史**——git 确实提供外部见证，但只有在 CI 把基线指向变更前的 commit 时才成立；本地 `HEAD` 是空操作（对比的是自己）。而且"未提交就被改"这个窗口里毫无保护。git 与封印史解决的是不同问题，两者都要。
- **什么都不做，只在文档里警告**——本项目的前提就是"写在散文里的规矩等于没有规矩"，用警告替代机制与自身立场矛盾。

## Consequences

- **收益**：篡改、删除封印、重排历史、手工投放归档笔记都会在下次校验时失败；`--reseal` 让"我知道自己在改写冻结区"成为一次需要写进提交信息的显式动作。实测覆盖：删除 manifest 后 `--write` 拒绝重建、丢弃封印史条目报断链、原地改写早期封印报断链、基线对照下重封篡改内容被抓住。
- **代价与已知上限**：封印史与 manifest 都在同一个仓库里，有写权限的人可以连它们一起改写。**本地封印只能留痕，不能防篡改**——真正的证明来自 CI 里指向变更前 commit 的外部基线。这个上限写进了 `references/archiving.md`、README 和两版 `SKILL.md`，并让脚本在缺少 git 见证时打印明确警告而不是静默通过。

## Verification

- `npm run test-gates` 中的 seal 用例覆盖：首次建立基线、篡改被检出、`--write` 无法重封、丢失 manifest 拒绝重建、`--reseal` 显式采纳、丢弃封印史条目、原地改写封印、以及 git 基线下的三种攻击。
- 链完整性由 `verifyChain()` 单点实现，`seal-store.ts` 被归档 CLI 与校验器共用，避免两处实现漂移。
