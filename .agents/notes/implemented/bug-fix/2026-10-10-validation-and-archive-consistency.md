# Agent Note: 笔记校验保留原始事实，归档先检查再批量更新

Status: implemented

## Problem

审查发现门禁会漏掉 `.zh.md` 内容、缺失的索引条目和账本尾条；无效显式 Git 引用会退化为通过。归档命令先移动源文件再检查账本，失败留下半成品。浏览器和打包看板各自解析正文，导致段落与别名表现不同。串行破坏同一个测试夹具还会让较早错误掩盖目标检查。

## Decision

活跃笔记及配对文件分别接受格式与链接校验，首个真实二级标题必须是 Problem 或支持的别名。`note-parser.mjs` 统一过滤代码示例、引用和注释；Node 与生成的浏览器页面使用相同解析逻辑和词汇表，并保留完整小节正文。

封印校验不修改读入的索引。账本链、索引条目、磁盘文件与摘要分别核对；显式 Git 基线解析或读取失败直接报错，原始 implemented 路径遵循 `AGENT_NOTE_ROOT`。缺少账本必须恢复；`--reseal` 不能修复损坏链或绕过后续历史比较。封印定义继续以[封印账本](../architecture/2026-10-09-append-only-seal-ledger.md)为准。

归档先验证固定头部、目标、后继笔记和已封印内容，再准备快照、两份封印及可选后继链接。`Archived:` 只插入头部，正文示例不参与判断，原始 BOM 和换行保留。源文件最后删除；严格模式发现入站链接时不写文件。普通 I/O 失败时尝试恢复已改文件，恢复失败明确报告原始错误和需恢复的路径。

技能入口区分“不新增笔记”和“同步已有事实”；只记录真实备选，不要求最低数量；仅对尚未授权的重要取舍确认。已授权工作直接完成。

## Alternatives considered

- 保留两份解析器并补齐正则：已发生多次漂移，共用无文件系统依赖的解析器减少维护分叉。
- 无效显式基线只给警告：会让 CI 配置错误看起来通过，因此只允许未配置基线且 Git 不可用时明确降级。
- 只增加归档前检查：无法处理写入中途失败，因此增加少量关联文件的备份和恢复；不引入数据库或持久事务日志。

## Consequences

校验错误更容易定位，失败归档通常不需要人工拼回源文件。批量更新的内存占用与相关文件总字节数成正比；调用方必须串行写入，不保证断电、进程终止或恢复本身失败时的跨文件原子性。再次操作前应校验，并从可信版本恢复不一致状态。

## Verification

`npm run test-gates` 使用独立损坏夹具并检查目标诊断，覆盖配对内容、示例链接、首节顺序、缺失元数据、自定义根目录、无效 Git 引用、正文归档标记和注入写入故障后的恢复。生成页面内嵌解析器在 Node VM 中与打包结果比较；当前环境没有 Browser 插件或 Playwright，未验证实际浏览器交互。安装交付由 `npm run test-skill-install` 检查。
