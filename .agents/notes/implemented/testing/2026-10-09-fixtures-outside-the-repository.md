# Agent Note: 测试夹具放在仓库之外，避免把仓库自己的 git 历史当成基线

Status: implemented

## Problem

归档封印依赖一个"外部见证"：`AGENT_NOTE_ARCHIVE_BASE_REF` 指向的 commit。校验器通过 `git rev-parse --show-toplevel` 从笔记目录向上找仓库根，再拿该基线里的 `manifest.json` 与当前工作区比对。

门禁回归套件原先在工作区**内部**创建临时宿主项目（`.gates-scratch/`）。在仓库还没有 `.git` 时这没问题；仓库发布后变成 git 仓库，夹具便开始向上找到**本仓库的 `.git`**，于是：

- `git show HEAD:<夹具相对路径>` 在实际仓库历史上查找，找不到就退化成"跳过对照"；
- 夹具的"当前状态下要拒绝"与"合规状态下要接受"两类断言，同时出现误判——实测一次性打挂 8 个用例。

失败原因与封印逻辑无关，纯粹是测试环境串味；而不看日志的话，它极易被误读成脚本回归。

## Decision

所有门禁夹具建在仓库之外的系统临时目录（`os.tmpdir()`），每个夹具自成一个独立的 git 仓库（需要 git 语义的用例），与宿主仓库再无父子关系。

`test-gates.mjs` 只依赖 Node 标准库与 git，不联网；需要联网的安装测试单独放在 `test-skill-install.mjs`，两者分属 `npm run test-gates` 与 `npm run test-skill-install`。

## Alternatives considered

- **在夹具里设 `AGENT_NOTE_ARCHIVE_BASE_REF` 指向一个空的初始提交**——能让比对有确定的基线，但夹具仍然住在仓库内，任何一次"向上找根"的行为都会先撞上本仓库的 `.git`；这是在跟症状搏斗，而不是消除原因。放弃。
- **让校验器只认显式配置的仓库根，不做向上查找**——会改变产品行为：宿主项目里笔记目录常常不在仓库根，向上查找是合理默认。为一个测试便利去改产品语义，方向反了。放弃。
- **把 `.gates-scratch/` 加进 `.gitignore` 当作解决**——gitignore 不改变 git 的仓库边界，向上查找照样命中本仓库。实测证明无效。
- **每次运行前删掉自己创建的文件并复查**——夹具已经被 `rmSync` 清理；问题不在残留，而在**存在期间**的仓库归属。放弃。

## Consequences

- **收益**：夹具与宿主仓库彻底解耦，断言只反映被测脚本的行为；`os.tmpdir()` 也避免了在仓库里留下可被误提交的目录。
- **代价与已知上限**：夹具不再受仓库的 `.gitignore` 保护，因此清理必须可靠——测试用 `try/finally` 包裹并在结尾 `rmSync`。Windows 上文件句柄偶尔会延迟释放，清理失败不影响断言结果，只会留下临时目录。另一个代价是夹具无法复用仓库内的相对路径假设，所有路径必须显式构造。

## Verification

- `npm run test-gates` 在全绿状态下工作树保持干净（无 `.gates-scratch` 残留）。
- 该缺陷的判定标准：把夹具移回仓库内应重新出现基线误判；移出后 50 项全绿。
