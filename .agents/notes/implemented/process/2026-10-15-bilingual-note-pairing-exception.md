# Agent Note: 本仓库的英文笔记另存为 `-en.md`，用结构同步守卫兜底

Status: implemented

## Problem

技能定义了可选的翻译配对约定：`<base>.md` + `<base>.zh.md`，由 `verify-agent-note-tree` 强制"变体必须有基础文件"。本仓库把两篇中文笔记另存了一份英文（`2026-10-09-append-only-seal-ledger.md` / `…-ledger-en.md`，另一篇同理），后缀是 `-en.md`，不是 `.zh.md`。

后果有两条：其一，这两对笔记完全绕开配对校验，没有任何机制保证同步，会随时间各自漂移；其二，约定与实际做法不一致，后来者无法从文档判断 `-en.md` 是有意为之还是历史残留。同一轮评审还指出文档与门禁的三处小漂移（CI 注释的断言数、`README` 的宿主脚本名、`verification.md` 记录的旧环境变量名），它们与本文同因：事实变了而书面记录未跟随。

## Decision

**保留 `-en.md` 作为本仓库自觉的例外，并为它补一个真实机制。** 技能侧不再新增第二条语言规则：`.zh.md` 约定描述的是"同一篇笔记的变体"，而本仓库这两对是**各自语言的决策记录**——中文版是原稿，英文版面向英文读者，正文各自成文而非逐句对译。二者靠"同一文件名基底 + `-en` 后缀"对应。

新增共享脚本 `verify-bilingual-notes.ts`，只比较可机械核对的表面：二级标题序列、文件名中的首次提出日、状态行。正文语义不比较（守卫不了，也不该假称能）。它已并入本仓库的 `verify-notes` 与 `verify-notes-en`，两版逐字节相同。

同批修正三处文档漂移：`.github/workflows/verify.yml` 的断言数由 50 改为当前值；`README.md` 的宿主脚本示例统一为 `archive-agent-note`；`references/verification.md`（中英两版）改为主用的 `AGENT_NOTE_CODE_ROOTS` 并注明单数旧名兼容。`test-gates` 的漏译守卫从只扫 `SKILL.md` 扩到英文版全部文档，允许清单补入门禁接受的中文状态行写法。

## Alternatives considered

- **改用 `.zh.md` 把中文版标为变体** —— 唯一能直接复用现有配对校验的做法。但文件名以英文主题命名（`append-only-seal-ledger.zh.md`）而内容是中文原稿，语义倒置，且会让"变体"目录约定承担它没设计的角色。放弃。
- **换成英文基底 + `.zh.md` 中文变体** —— 语义自洽，配对校验直接生效。代价是两篇中文笔记要重命名（它们被其他笔记与提交信息引用），且把"中文是这个仓库的原稿语言"这一事实在文件名层面抹掉。收益不足以支付改名成本。放弃。
- **只写本文说明例外，不加任何校验** —— 零成本，也满足评审"记录例外"的最低要求。但"没有机制保证同步"正是被指出问题的核心，只补文档等于把同一处隐患换个地方存放。放弃。
- **比较两版正文语义是否等价** —— 理想守卫。但语义等价无法用脚本判定，假装能判会让门禁给出虚假保证。退到可机械核对的表面。放弃。

## Consequences

- **收益**：`-en.md` 从"无人看管的约定"变成有守卫的约定；结构分叉或状态不一致会以非零退出暴露。文档与门禁在环境变量名、脚本名、断言数三处恢复一致。
- **代价与已知上限**：守卫只覆盖结构与元数据，**英文版可以结构正确而语义过期**（中文版改了论证，英文版没跟上仍会通过）。出现"中文版结论已变"的信号时，必须人工同批更新英文版。守卫依赖文件名后缀，重命名笔记会同时改变配对关系。
- 技能侧的门禁契约不变：`verify-bilingual-notes.ts` 是本仓库自用，不进入宿主必须运行的三个门禁。

## Verification

`npm run verify-notes` 与 `npm run verify-notes-en` 都新增一行 `ok: 2 bilingual note pair(s) in sync`。`npm run test-gates` 断言：结构同步的两版通过；只给英文版加一节报 `section skeleton differs`；只有 `-en.md` 没有基础文件报 `English note has no base note`。当前 111/111 通过。
