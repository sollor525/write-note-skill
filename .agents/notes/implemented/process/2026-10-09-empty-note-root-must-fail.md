# Agent Note: 门禁在空笔记根下必须报错，而不是打印 ok

Status: implemented

## Problem

三个校验脚本原本在**一篇笔记都没找到**时打印 `ok: 0 note(s) verified` 并退出 0。三种常见误用因此全部表现为"校验通过"：

- 从错误的当前目录执行（例如在 skill 目录里跑，而不是宿主项目根目录）；
- `AGENT_NOTE_ROOT` 指向了空目录或写错的路径；
- 宿主项目的笔记还没建。

这个脚本的读者是 Agent。路径搞错恰恰是 Agent 最常见的失败，于是最可能的结局是：Agent 跑完校验、看到全绿、向用户报告"校验通过"，而实际上一篇笔记都没有被检查过。一个在"什么都没检查"时给出成功信号的校验，比没有校验更危险。

## Decision

`verify-agent-note-tree.ts` 与 `verify-agent-note-format.ts` 在 `notes.length === 0` 时以非零退出，并打印两行可操作的诊断：说明在哪个根目录下没找到笔记，以及两条修法（在宿主项目根目录运行，或用 `AGENT_NOTE_ROOT` 指向笔记目录）。

`verify-archived-agent-notes.ts` **不受此规则约束**：归档区为空是完全合法的状态（新项目还没归档过任何东西），在那里报错会把正常仓库判红。

## Alternatives considered

- **打印警告但仍然退出 0**——门禁的价值完全来自退出码。CI 与 Agent 读的是退出码，警告会被忽略，等于没有改。放弃。
- **三个脚本统一在空根时报错**——`archived/` 为空是正常且常见的新仓库状态，这样做会让所有新项目开箱即红，并诱导用户加豁免开关。放弃。
- **只警告，靠文档提醒使用者不要在错目录运行**——本项目的前提就是"能机械检查的纪律都交给脚本，不靠散文"。用文档提醒替代退出码与自身立场矛盾。放弃。
- **在空根时自动向上搜索 `.agents/notes/`，找到一个就用**——隐式改变检查对象，会让"到底检查了哪个目录"变得不可预测；显式退出并告诉用户修法更诚实。放弃。
- **把空根与"根本没有 `.agents/` 目录"区分对待，前者报错、后者放行**——两者对使用者是同一件事（没有笔记被检查），区分只会制造第二套心智模型。放弃。

## Consequences

- **收益**：路径配错立刻红，附带可执行的修法；"校验通过"重新等于"确实检查了 N 篇笔记"。空根缺陷就是靠这条规则在 CI 里暴露出来的——仓库自己没有 `.agents/notes/`，于是 `gates` 作业第一步失败，而不是安静地全绿。
- **代价与已知上限**：新仓库在写下第一篇笔记之前，这两条命令会失败。这是刻意的：门禁服务的对象就是笔记，没有笔记时它没有可检查的内容，"通过"是误导。已知上限是它无法区分"还没有笔记"与"路径错了"——两者给出的诊断因此写得足够宽，覆盖两种可能。

## Verification

- `npm run test-gates` 断言：空根下 tree 与 format 都以非零退出，同一个空根下 archived 以 0 退出。
- 该规则在本仓库自身上生效：`.agents/notes/` 不存在时 `npm run verify-notes` 失败（CI 的 `gates` 作业因此暴露了这一矛盾）。
