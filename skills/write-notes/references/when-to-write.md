# 按需阅读：何时写、何时改与决策流转

> 展开 SKILL §1 的判断顺序与 §4 的状态流转。判断是否记录或如何更新时读取。

## 核心心智：更新既有归属，严禁重复新建（Update the owning note）

长期维护的笔记库里反复出现同样的形态：Note 的新增很少，现有 Note 的**就地事实修正**占了绝大多数。
**不要把 Note 当做一次性发表的博客或流水账。它是与代码共存亡的「现行法律」。**

一篇 Note 永远不被改写成另一个决定：事实（路径、符号、默认值）就地改；决定或理由翻转 → 新开一篇并互链。禁止把 `## Decision` 改写成反面，禁止只靠 git 当旧理由的唯一副本。

---

## 1. 按顺序选择动作

先读宿主约定、查找决定归属，按下表第一项匹配情况处理，之后才选类别。

| 情况 | 动作 | 例子 |
|---|---|---|
| 已有决定、理由不变、事实变化 | 更新归属记录 | 模块改名或超时调整后同步事实，不重复建笔记 |
| 已有决定或理由反转 | 新建后继，保留旧理由 | 新的持久化要求取代纯内存队列 |
| 无归属，但新增长期约束、契约或不显然的取舍 | 新建笔记 | 下游服务必须遵守新的报文版本或一致性边界 |
| 无受影响的决策事实，代码与测试之外没有新理由 | 不新增笔记 | 修复边界判断，恢复已写明的数量上限 |

行为变化需要作上述判断，但不自动要求笔记。常规 CRUD、格式、样式、明确改名、不改变行为的依赖补丁，若不影响已有决策事实就无需记录。很小的改动若承载重要运行取舍，仍需记录。复盘在发现长期约束或预防规则时值得成文，不是只因发生了错误就成文。

新建前把相关记录分为无关、部分重叠、完全吸收、尚未实现且明确放弃的提案。部分重叠互链，不悄悄改写旧选择。

## 宿主格式与授权边界

已有 ADR 保留宿主的布局、状态词和检查；上述判断不要求导入本技能的头部、目录、索引或归档规则。`AGENT_NOTE_ROOT` 不是格式迁移工具，详见[校验说明](verification.md)。

能查明的事实自行查明。只有未获授权的迁移、兼容性边界等重要未决选择需要集中询问；已授权工作不再次确认。需要新决定的实现先写提案，完成后移动同一篇记录，不为“完成”另建一篇。

## 2. 原地同步法则（In-place Fact Sync）

当现有 Note 所守护的模块发生演进，但核心决策并未被推翻时：

1. **直接修改，不记流水账**：
   - ❌ 错误：在文末追加 `### 2026-09-02 更新：类名重命名为 X`
   - ✅ 正确：直接在正文中将旧类名替换为新类名，保证任何时候打开这篇 Note，它反映的都是 HEAD 分支的绝对事实。
2. **时态永保现在时**：
   - 始终使用现在时（`系统使用 SQLite 作为持久化引擎`），严禁使用变更叙事（`系统不再使用 JSONL，现在使用 SQLite`）。门禁只拒提案标题，现在时靠这条纪律，不靠词法扫描。

---

## 3. proposed → implemented 改写清单

按方案是否实现判断状态：工作完成而没有待办，应转 `implemented`；只有尚未实现且明确放弃的方案才转 `rejected`。

同一次改动里做完：

1. 移到 `implemented/<class>/`，文件名日期不动（首次提出日）
2. `Status: proposed` → `Status: implemented`
3. `## Proposal` → `## Decision`，改成现在时（已落地的事实）
4. `## Acceptance criteria` / `## Risks` 折进 `## Consequences`（或现在时 `## Testing` / `## Verification`）
5. 删计划段（`## Plan` / 迁移步骤 / 开放问题）

门禁靠骨架变化卡住：implemented 里残留 `## Proposal` 会失败。

---

## 4. 取代：部分重叠 vs 完全吸收

**部分重叠**：新方案只覆盖旧方案一部分 → 两篇都留，双方加相对链接。在旧篇 `Problem` 开头醒目标明被替代的范围及后继链接，保留原理由与仍有效的决定；只在仍有效的范围内同步事实，不归档仍在生效的记录。

**完全吸收**（旧方案被彻底淘汰）：

1. **审计旧 Note 资产**：独有的安全边界、否定性保证、失败场景、重新引入条件、验证缺口。
2. **搬迁与吸收**：写入新 Note 的 `## Decision` / `## Alternatives considered` / `## Consequences`。
3. **旧 Note 二选一**：
   - **删除**：新篇已写入旧篇全部独特内容，且入站链接已改完 → 物理删除，不进 `archived/`。
   - **归档**：旧篇还有独立杠杆（否定性保证、所有权边界、重新引入条件）→ `archive-agent-note.ts`。只插 `Archived:` 一行；互链写在新笔记。
4. **修复入站链接**：把仍指向旧路径的相对链接改到新 Note（引历史快照时才指向 `archived/`）。

`--superseded-by` 校验后继路径属于另一篇活跃笔记，并在其最后一个小节之前补上指向归档路径的相对链接；已存在等价链接时不重复插入。

```typescript
}
```

不是门禁。`check-note-anchors` 只做软报告，不进 CI。
